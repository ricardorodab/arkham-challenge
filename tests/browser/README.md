# Browser acceptance fixtures

Run from the repository root after installing the locked Python/npm dependencies:

```powershell
npx playwright install chromium
npx playwright test
node tests/browser/summarize.cjs
```

`OUTAGE_TEST_PYTHON` can select another Python interpreter with the project and locked dependencies installed. Otherwise the runner uses `.venv/Scripts/python.exe` on Windows or `.venv/bin/python` on POSIX. Tests use one Chromium worker and start their own Waitress server on `127.0.0.1:8766`; an existing server is never reused.

Every run gets fresh `work/browser-state/<run-id>` and `work/browser-data/<run-id>` directories. Test-only credentials are explicit in `fixture.json` and exported as `FRONTEND_TEST_PASSWORDS` by `helpers.cjs`. The fixture overrides application state/data/secret configuration and removes inherited EIA credentials. It never reads `key.txt`, `.service/local-config.json`, or the operator's analytical data. These credentials and the fixture server are not deployment defaults.

The actual ingestion/model pipeline receives `tests.helpers.FakeClient`, with coherent synthetic national/facility/generator measures. There are three observed dates (September 1, 3 and 4, 2026), an intentionally missing September 2, two facilities and 40 generators per date. Fleet capacity is 2,000 MW and the observed offline shares are 10%, 0%, 20%. A successful synthetic refresh changes the last observation to 30%; a failing refresh leaves the prior publication current. Names deliberately contain a spreadsheet formula and markup-shaped text to test safe rendering/CSV export.

Operational resets occur before each test. Browser-triggered refreshes are consumed by separately spawned real `RefreshWorker` processes with the same synthetic client. Test teardown terminates unfinished workers; there are no live EIA requests or test-only HTTP control endpoints. The out-of-band Python control command is confined to these test directories and state.

The suite covers personas, protected navigation, keyboard controls, session revocation, scoped SQL history, chart/table/missing-data behavior, filters and pagination, CSV, errors and stale responses, real refresh outcomes and explicit snapshot adoption. Axe checks use WCAG 2/2.1 A/AA tags on desktop and 390×844 layouts. Automated accessibility checks supplement keyboard checks and visual review; an empty violations list is not a certification, and incomplete rules remain visible in the attached audit data.

Outputs:

- `work/browser-results/results.json`: complete Playwright JSON report, including axe attachments and the isolated fixture run ID.
- `work/browser-results/evidence.json`: concise machine summary generated by `summarize.cjs`.
- `work/browser-results/artifacts/`: desktop/mobile screenshots, plus failure traces/video when relevant.
- `work/browser-report/`: local HTML report (`npx playwright show-report work/browser-report`).

Only the current displayed page is exported. Browser preview/SQL tests exercise the real isolated query runtime; install the pinned npm runtime rather than substituting an API mock for those success paths. Route interception is used only for controlled loading, denial, retry and stale-response states.
